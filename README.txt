Сервис управления рассылками (курсовой проект на Django)
=======================================================

Кратко
— Веб‑приложение на Django для управления клиентами, сообщениями и рассылками: создание, редактирование, удаление, запуск рассылок и сбор статистики по попыткам отправки.

Статус
— Основная функциональность готова:
  • Кастомная модель пользователя с входом по email, регистрацией, подтверждением, восстановлением пароля.
  • CRUD для Получателей, Сообщений и Рассылок с разграничением доступа по владельцу.
  • Роли «Менеджеры»: отдельные права для просмотра всех объектов (view_all_*).
  • Запуск рассылок из UI (кнопка на странице детали) и management-командой.
  • Логирование попыток отправки (Attempt) и отчёты (список/детали) с агрегатами.
  • Главная страница со сводной статистикой.
  • Пагинация списков.
  • Кеш + инвалидация кеша сигналами моделей (см. раздел «Кеширование»).
— Автотесты покрывают ключевые сценарии (см. раздел «Тестирование»).

Требования
- Python >= 3.12,<4.0
- Poetry

Быстрый старт
1) Установите Poetry (если не установлен):
   Windows (PowerShell): (Invoke-WebRequest -Uri https://install.python-poetry.org -UseBasicParsing).Content | py -

2) Убедитесь, что Poetry использует Python 3.12:
   poetry env use py -3.12

3) Установите зависимости (ОБЯЗАТЕЛЬНО перед запуском любых manage-команд):
   poetry install

4) Создайте .env на основе примера:
   копируйте .env.example -> .env и при необходимости измените значения.

5) Примените миграции и запустите сервер разработки:
   poetry run python manage.py migrate
   poetry run python manage.py runserver

6) Зайдите в админку (опционально):
   poetry run python manage.py createsuperuser
   http://127.0.0.1:8000/admin/

Как зайти в админку и создать администратора
— Создайте суперпользователя (даёт доступ к /admin/):
  poetry run python manage.py createsuperuser
  Введите email и пароль. Этот пользователь получит is_staff=True и is_superuser=True.
— Запустите сервер и войдите в админку:
  poetry run python manage.py runserver
  Откройте http://127.0.0.1:8000/admin/ и авторизуйтесь данными суперпользователя.

Если нужно создать группу «Менеджеры»:
— Админка → Пользователи и группы → Группы → Добавить → Имя: «Менеджеры». Отметьте права:
  • mailings | recipient | Может просматривать всех получателей (view_all_recipients)
  • mailings | message  | Может просматривать все сообщения (view_all_messages)
  • mailings | mailing  | Может просматривать все рассылки (view_all_mailings)
— Сохраните группу и добавьте в неё нужных пользователей.
— Чтобы пользователь мог входить в админку, поставьте ему флаг is_staff=True (в карточке пользователя в админке).

Права «Менеджеров» (просмотр всех объектов)
— В проекте определены кастомные права на уровне моделей:
  • mailings | recipient | view_all_recipients
  • mailings | message  | view_all_messages
  • mailings | mailing  | view_all_mailings
— Пользователь с этими правами видит все объекты соответствующих сущностей в UI и в отчётах. Без прав видны только собственные объекты.

Аутентификация и подтверждение email
- Регистрация: http://127.0.0.1:8000/users/register/
  После отправки формы ссылка активации придёт «по email» в консоль сервера (мы используем консольный почтовый бэкенд). Откройте ссылку из консоли, чтобы активировать учётную запись и войти.
- Вход/выход/профиль:
  - Вход: http://127.0.0.1:8000/users/login/
  - Профиль: http://127.0.0.1:8000/users/profile/
  - Выход: http://127.0.0.1:8000/users/logout/

Сброс пароля (работает через консольный email)
- Запрос сброса: http://127.0.0.1:8000/users/password-reset/
- После отправки формы письмо со ссылкой появится в консоли сервера.
- Перейдите по ссылке из письма, задайте новый пароль, затем войдите с ним.

Переменные окружения (.env)
— Пример в .env.example. Ключевые:
- SECRET_KEY=...            # секретный ключ Django
- DEBUG=True|False
- ALLOWED_HOSTS=127.0.0.1,localhost
- SQLITE_NAME=db.sqlite3    # имя файла SQLite (по умолчанию)

Email (для разработки)
- EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend
— Письма выводятся в консоль. Для реальной отправки переключите на SMTP и заполните EMAIL_HOST, EMAIL_PORT, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD, EMAIL_USE_TLS/SSL.

SMTP (боевой режим)
— Пример настроек в .env.example. Минимально задайте:
  EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
  EMAIL_HOST=smtp.example.com
  EMAIL_PORT=587
  EMAIL_HOST_USER=your_login
  EMAIL_HOST_PASSWORD=your_password
  EMAIL_USE_TLS=True
  DEFAULT_FROM_EMAIL=no-reply@example.com

Команды управления
— Запуск рассылок из консоли (обработать все «в окне времени»):
  poetry run python manage.py mailings_send
— Запуск только одной рассылки по ID (если не завершена):
  poetry run python manage.py mailings_send --id 123

Кеширование и инвалидация
— Используется стандартный Django‑кеш (locmem по умолчанию в dev).
— Инвалидация реализована сигналами в mailings/signals.py и срабатывает при изменениях Attempt/Mailing/Recipient и при изменении состава получателей у рассылки.
— Важно: страницы, зависящие от состояния сессии (главная, отчёты), не кешируются целиком, чтобы корректно отражать авторизацию пользователя.

Тестирование
— Проект оснащён автотестами (pytest + pytest-django) для проверки прав «Менеджеров»,
  запуска рассылок (UI и management-команда), агрегатов отчётов, пагинации и инвалидации кеша сигналами.

Как запустить тесты
1) Установить зависимости:
   poetry install
2) Запустить тесты:
   poetry run pytest
3) По умолчанию используется SQLite и in-memory email backend (locmem) для проверки отправок писем.

Ручная проверка UI: чек‑лист
— Подготовка окружения
  1) Убедиться, что используется Python 3.12:
     poetry env use py -3.12
  2) Установка зависимостей:
     poetry install
  3) .env на месте (при необходимости скопировать .env.example → .env)
  4) Применить миграции:
     poetry run python manage.py migrate

— Запуск и базовая проверка
  5) Запустить сервер разработки:
     poetry run python manage.py runserver
  6) Открыть http://127.0.0.1:8000/ — страница открывается, в шапке ссылки «Вход/Регистрация».
  7) Проверить, что /favicon.ico не отдаёт 404; в консоле нет предупреждений об отсутствующей static‑папке.

— Регистрация, подтверждение email, вход/выход
  8) Открыть /users/register/, заполнить форму, отправить.
  9) В консоли сервера найти ссылку активации и перейти по ней — учётка активируется, выполняется вход, редирект в профиль.
  10) Выйти через /users/logout/, затем войти через /users/login/.

— Профиль
  11) /users/profile/ — проверка отображения полей.
  12) /users/profile/edit/ — изменить имя/телефон/страну, по желанию загрузить аватар и проверить его отображение.

— CRUD Получателей
  13) /mailings/recipients/ — пустой список, кнопка «Добавить».
  14) Создать получателя; проверить детали/редактирование/удаление и возвраты по URL.

— CRUD Сообщений
  15) /mailings/messages/ — создать сообщение; проверить детали/редактирование/удаление.

— CRUD Рассылок
  16) /mailings/mailings/ — создать рассылку: доступны только свои «Сообщения» и «Получатели».
  17) Проверить страницу деталей (статус, даты, список получателей), редактирование и удаление.

— Доступ и навигация
  18) Убедиться, что ссылки «Получатели/Сообщения/Рассылки» видны только авторизованным.
  19) Без авторизации переход на любой URL из разделов ведёт на /users/login/.
  20) Под другим пользователем не видны сущности первого (фильтрация по владельцу).

— Сброс пароля (консольный email)
  21) /users/password-reset/ — ввести email, получить письмо в консоли, перейти по ссылке, задать новый пароль и войти с ним.

Частые вопросы и ошибки
— ModuleNotFoundError: No module named 'django'
  Причина: виртуальное окружение Poetry создано, но зависимости ещё не установлены.
  Решение: выполните poetry install в корне проекта, затем повторите команду, например:
    poetry install
    poetry run python manage.py migrate

— Poetry использует не тот интерпретатор Python
  Решение: укажите нужный Python вручную и пересоздайте окружение:
    poetry env use python
    poetry install

— OperationalError: no such table: mailings_recipient (или другая таблица)
  Причина: миграции приложений ещё не применены к текущей базе данных (db.sqlite3 была создана раньше, чем появились модели/миграции).
  Решение:
    1) Применить миграции:
       poetry run python manage.py migrate
    2) Если ошибка остаётся, пересоздайте локальную БД (данные удалятся):
       - Остановить сервер разработки (если запущен)
       - Удалить файл db.sqlite3 в корне проекта
       - Запустить миграции заново: poetry run python manage.py migrate
    3) Перезапустить сервер: poetry run python manage.py runserver
